# Clay working rules

Preserve Clay's Scratchpads/Pieces design, app-family typography, and local persistence/recovery behavior. Read README.md, TEST_REPORT.md, DISTRIBUTION.md, SYNC.md, and Release/project-destinations.json for current scope and verified delivery evidence.

The user requires the canonical local source folder, GitHub repository `https://github.com/briggskellogg/clay`, and Proton Drive `[projects]/clay` to stay synchronized after completed Clay changes. This is a source-only workflow: follow SYNC.md to fetch/reconcile, validate, review/stage, check privacy, commit/push without force, conservatively mirror tracked source, and verify Proton's completed upload. Record any unfinished destination accurately. No background source-sync service is implied.

The owner's later November 8, 2026 instruction explicitly adds private writing synchronization and confirms the same personal iCloud Drive account on iPhone, Mac, and Windows PC. This supersedes build 3's source-only implementation scope. Build 4 implements a dedicated user-selected personal iCloud Drive/Clay folder, with private `ClaySync/Records` and `ClaySync/Exports/<deviceID>` subfolders. The local private `Clay/SyncJournal` retains offline history. Actual connection and cross-device verification remain pending until recorded otherwise. Do not infer them from a build or a local folder write.

Private writing, document metadata, sync records, readable exports, local libraries/recovery folders, credentials, signing-local configuration, and build caches must never enter GitHub or the Proton source mirror. Keep private storage outside repositories and `[projects]`. Before committing/pushing, run `python3 scripts/check-source-privacy.py --staged` and review the staged files. The guard catches known runtime paths and formats, not arbitrary private prose; it is not a substitute for keeping data out of source.

Windows reads derived Markdown snapshots in the private iCloud folder; edits to those exports do not import into Clay. No Windows native app or PC backup jobs are created by this release. Keep any personal-data Proton backup separate from `[projects]/clay`; use only an independently confirmed personal-folder scope and verified backup destination. Never infer that an external backup pipeline is configured or current from source-sync success.

Desktop installation belongs at `/Applications/Developer/Clay.app`; preserve app data and the previous installation. Keep App Store Connect/TestFlight named **Clay by Briggs Kellogg**, the existing app/bundle IDs, and the internal Briggs group. Phone delivery is through TestFlight; a simulator launch or exported IPA does not prove installation on the owner's phone. Build 3 is the latest verified Testing release while build 4 awaits validation and delivery. Preserve GitHub's existing visibility unless the user requests a change.
